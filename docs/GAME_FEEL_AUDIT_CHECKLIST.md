# 게임 필(Game Feel) 감사 체크리스트

이 문서는 게임 내 주요 사건/상호작용의 "체감"을 점검하기 위한 반복 사용 가능한 프레임워크다.
효과를 더 많이 넣는 것이 목표가 아니라, **의도가 명확하고 일관되며 플레이어가 행동의 원인과 결과를 즉시 이해할 수 있는 상태**를 만드는 것이 목표다.

---

## 1. 분석 흐름

각 사건(공격, 피격, 아이템 획득, 버튼 클릭, 보스 등장 등)을 아래 흐름으로 쪼개서 분석한다.

> 입력 → Anticipation(준비) → 행동 → 충돌/변화 → 결과 → Recovery/정착

---

## 2. 확인 요소 체크리스트

각 사건에 대해 아래 항목을 확인한다.

- 입력 직후의 시각 / 청각 / 햅틱 피드백
- Tween / Lerp / Easing을 활용한 움직임과 수치 변화
- Anticipation / Squash & Stretch / Follow-through / Secondary Motion
- Hit Stop / Hit Flash / Knockback / Screen Shake 등 전투 피드백
- Particle / Trail / Impact / Afterimage 등 시각 효과
- Damage Preview / Trailing Health Bar / Count-up 등 상태 변화 표현
- Camera Zoom / Camera Kick / 이동 / 추적 등 카메라 연출
- 등장 / 획득 / 레벨업 / 사망 / 퇴장 과정
- 화면 전환 / 결과 화면 / Victory / Game Over 연출
- 버튼의 Hover / Press / Release / Disabled 상태 (단, 모바일 등 해당 플랫폼에서 의미 없는 상태는 제외)
- 정보 위계와 UI 가독성
- UI 및 게임 오브젝트의 등장·퇴장 타이밍
- 사운드와 화면 효과의 동기화
- 모바일이라면 Haptic Feedback의 적절성
- 반복 플레이 시 지나치게 길거나 지루해지는 연출
- 여러 효과가 같은 정보를 중복 전달하거나 서로 시선을 방해하는 문제

---

## 3. 평가 기준

각 항목에 대해 다음 다섯 가지를 평가한다.

1. 현재 구현 여부
2. 문제점
3. 개선 효과
4. 구현 난이도
5. 우선순위

**원칙:** 이 게임에서 체감 효과가 큰 것만 제안하고, 불필요하거나 과한 효과는 제외한다.

---

## 4. 코드/연출 정리 점검

프로젝트 전반에서 아래를 찾아 **유지 / 통합 / 삭제** 중 하나로 제안한다.

- 중복된 연출
- 중복된 코드
- 사용하지 않는 기능
- 역할이 겹치는 UI
- 스타일이 다른 요소

---

## 5. 우선 탐색 대상: "로직은 있지만 표현이 부족한 사건"

가장 먼저 찾아야 할 것은 로직상 이미 작동하지만 체감 연출이 빠진 사건이다.

예:
- 공격은 되지만 맞았다는 느낌이 약함
- 몬스터는 죽지만 죽었다는 과정이 없음
- 아이템은 얻지만 획득감을 못 느낌
- 버튼은 작동하지만 눌렀다는 반응이 없음
- 레벨업은 되지만 숫자만 바뀜
- 보스가 등장하지만 일반 몬스터와 체감 차이가 없음
- 승리는 되지만 감정적인 마침표가 없음

---

## 6. 연출 강도는 중요도에 비례

모든 사건에 동일한 수준의 Screen Shake, Particle, Sound, Zoom을 적용하지 않는다.

- **일반 행동**: 최소한의 피드백
- **중요한 행동**: 명확한 피드백
- **클라이맥스**: 강한 피드백 (단, 반복 재생 시 피로하지 않게 조절)

---

## 7. 연속된 경험으로서의 시퀀스 검토

중요한 시퀀스는 개별 효과 단위가 아니라 **연속된 경험**으로 검토한다.

예 — 보스 마지막 공격 ~ 승리 화면:

> 마지막 공격의 임팩트 → 보스 사망 인지 → 짧은 여운 → Victory → 보상 표시

단, 반복 플레이를 방해할 정도로 길어지지 않게 설계한다.

---

## 8. 결과 정리 순서

감사 결과는 항상 아래 순서로 정리해서 제시한다.

1. **즉시 수정하면 효과가 큰 것**
2. **적은 비용으로 개선 가능한 것**
3. **나중에 다듬을 디테일**
